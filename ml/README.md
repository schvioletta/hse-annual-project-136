# ml: модели чекпоинта 3

Общая основа для всех экспериментов: один сплит, один набор признаков, одни метрики.
Иначе результаты разных людей нельзя сравнить.

## Как пользоваться

Файл с данными лежит в `data/raw/hu_dayahead_2024_2025.csv` (см. `data/raw/README.md`).

```python
from dayahead.split import load_splits
from dayahead.metrics import evaluate

s = load_splits()
# s.X_train, s.y_train, s.X_val, s.y_val, s.X_test, s.y_test

model.fit(s.X_train, s.y_train)
evaluate(s.y_val, model.predict(s.X_val))
```

Рабочий пример: [00_base.ipynb](00_base.ipynb).

## Сплит

По времени Будапешта, без перемешивания:

| Часть | Период | Для чего |
|---|---|---|
| train | 2024 (с 8 января, первые строки без недельных лагов отброшены) | обучение |
| validation | январь-июнь 2025 | подбор гиперпараметров и признаков |
| test | июль-декабрь 2025 | итоговая оценка, один раз в конце |

Итоговая оценка: модель с выбранными на validation настройками переобучается на
`s.X_trainval`, `s.y_trainval` (train + validation) и один раз проверяется на test.
Так она видит полгода, ближайшие к test.

Случайный сплит и обычный `KFold` не используем: через лаги цены модель увидит будущее.
Для кросс-валидации внутри train подходит `TimeSeriesSplit`.

## Признаки

Базовый набор, 17 штук (`dayahead.features.BASE_FEATURES`):

- прогнозы на сутки вперёд: спрос, солнце, ветер, АЭС, температура, сальдо обмена;
- календарь: `hour`, `dow`, `is_weekend`, `is_holiday` (праздники Венгрии);
- `residual_load` = спрос - солнце - ветер - АЭС;
- история цены: `price_lag_24`, `price_lag_48`, `price_lag_168`, скользящие среднее и
  стандартное отклонение за сутки, среднее за неделю. Окна заканчиваются за 24 ч до прогнозируемого часа.

Правила:

- Аукцион на сутки D проходит в D-1, поэтому из истории цены можно брать только то, что старше 24 ч.
  Функция `dayahead.features.lag` на меньший сдвиг выдаёт ошибку.
- `hour` и `dow` это категории, записанные числами. Для линейных моделей и KNN их нужно
  кодировать (one-hot или sin/cos).
- Месяца в базовом наборе нет: train покрывает один год, и месяц запоминает уровень цен 2024.
- Масштабирование и кодирование каждый делает сам внутри `Pipeline`, чтобы параметры
  считались только по train.

Свои признаки добавляются до сплита:

```python
from dayahead.features import TARGET, lag
from dayahead.split import load_features, make_splits

feat = load_features()
feat["price_lag_72"] = lag(feat[TARGET], 72)
s = make_splits(feat)
```

Пропуски от новых лагов в начале train отбрасываются. Пропуск в validation или test это ошибка:
состав строк там у всех должен совпадать.

## Метрики

`evaluate(y_true, y_pred)` возвращает словарь:

- `MAE`, `RMSE` по всем часам;
- `MAE_le0`: MAE на часах с ценой <= 0;
- `MAE_gt300`: MAE на часах с ценой > 300 EUR/MWh.

MAPE не считаем: цена бывает нулевой и отрицательной. Ключевая метрика согласуется с куратором.

## Бейзлайн

Цена вчера в этот час (`price_lag_24`). Числа в [00_base.ipynb](00_base.ipynb).
Модель имеет смысл, только если она лучше бейзлайна на validation.
